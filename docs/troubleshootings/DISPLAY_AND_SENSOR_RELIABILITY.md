# 显示与采集可靠性、局部刷新踩坑记录

## 1. NOLOAD 缓冲区不能先取得已初始化引用再清零

原 `init_frame_buffer()` 对 `MaybeUninit` 调用 `assume_init_mut()` 后再 `fill(0)`。
即使最终写满整个数组，取得引用时内存还没有初始化，已经违反 Rust 的安全约束。

修复：先通过原始指针 `write_bytes` 初始化 AXISRAM，再创建数组引用。
缓冲区只能领取一次，由 `DisplayDriver` 独占，绘图不再重复创建全局可变引用。
AXISRAM 位于 D1 域。当前实际传输是有界阻塞 SPI，没有启用硬件 DMA。

## 2. 传感器共享总线，不应销毁驱动或绑定成功分支

原流程只有 AHT20 读取成功，才把总线交给 BMP280。
AHT20 断开时，正常的 BMP280 也停止更新；BMP280 的错误又被静默忽略。

现在由 `acquisition::Sensors` 持久保存驱动状态，两者逐次借用同一个 `&mut I2C`。
每个传感器独立读取、独立重试初始化，BMP280 的校准参数保持在同一个实例中。
此前通过 `release/attach` 维护总线所有权的方式已被替代。

BMP280 未检测到器件必须返回 `DeviceNotFound`，不能返回初始化成功。
零值或全一的关键校准参数会被拒绝，初始化后等待首次转换，并拒绝复位态原始值。
AHT20 初始化后复查校准位；读取时也检查数据帧的 busy/calibrated 状态。

## 3. 零度是真实数据，不能用作未初始化标志

原统计逻辑在最高/最低值为零时重新初始化，导致 `0°C → 5°C` 的最低值变成 `5°C`。
现在根据有效样本计数识别首次采样，非有限值不会污染历史。

没有成功样本时显示 `--`；首次采集前显示 `WAIT`，采集失败显示 `ERROR`。
已有有效样本后失败则保留旧值并显示 `STALE`，同时保存最后成功的硬件时间戳。
温度和湿度继续使用各自的数据对象和历史记录。

## 4. 上层重试次数不能限制 HAL 内部死循环

HAL 0.16 的阻塞 I2C 以及原 SPI 等待内部可能无限轮询。
在外围写 100 次重试，无法打断已经卡住的单次调用。

I2C1 现在保留 HAL 的引脚、时序初始化，通过 PAC 执行有期限的事务：
一次事务期限 10ms；故障时尝试 STOP（最多 1ms），清标志并重新启用控制器。
SPI 使用非阻塞 FIFO 收发，每块发送/完成等待上限 100ms，错误向上传递。
事务出错会释放 CS，后续重新初始化屏幕并重发整帧。

控制器恢复不能保证解除外部器件持续拉低 SDA/SCL 的物理故障；这类故障会持续返回超时，
需要检查连线、供电和上拉。正常采集与控制器超时恢复已实板验证，见第 9 节；
持续拉低总线的物理故障仍需单独验证。

## 5. 绘制帧缓冲不等于刷新屏幕

卡片仅创建一次。更新时绘制动态区，通过 `FlushTarget` 明确刷新。
三张卡片的动态区各为 98×115，全部变化时像素数据为 67,620 字节，
原整屏为 153,600 字节，减少约 56%（不含窗口命令、独立底栏刷新）。
内容不变时跳过卡片传输。窄矩形的多行会打包进同一传输块，避免逐行启动 SPI。
刷新区域会裁剪，空区域直接跳过，坐标计算避免 `u16` 加法溢出。

TIM2 按 1MHz 自由运行；采样以 5 秒期限调度，使用回绕减法，错过期限后跳过积压任务。
它不再用主循环次数推算时间。32 位计数器约 71 分钟回绕，必须在一次回绕内轮询调度。

原 ESP8266 通信逻辑保留，但默认关闭启动和主循环重试（`ESP8266_ENABLED = false`）。
其阻塞流程会推迟主循环，定时器调度不会抢占它，不能直接重新启用。详见第 10 节。
本次没有更改 ESP8266 协议，也没有引入硬件 DMA。

## 6. macOS 主机测试不能链接 MCU 中断向量

第一次执行主机测试时，STM32 PAC 的 `rt` 特性产生 `.vector_table.interrupts`，
该 ELF section 名称不符合 macOS Mach-O 格式，LLVM 编译失败。

修复：把 HAL、Cortex-M 和 panic-halt 放到 Cargo 的 ARM 专用依赖区。
驱动解析、采集编排、UI 和调度在 `no_std` 库中共享，主机测试直接运行同一份代码。

验证入口：

```sh
make test   # 主机回归测试
make check  # 格式与默认配置 Clippy
make build  # ARM release 固件
```

回归测试覆盖设备缺失和恢复、独立采集、参考气压补偿结果、校准失败、忙状态期限、
零度统计、计时器回绕、矩形裁剪、跨行 RGB565 打包、SPI 超时和错误传递、
局部刷新与全屏绘制逐像素一致、刷新失败后的脏区域保留。

实板建议检查：冷启动、任一传感器拔插、I2C 卡线后的超时返回、横屏显示、
长期运行跨计时器回绕。主机测试不能代替对实际 SPI/I2C 时序的检查。

## 7. OpenOCD `open failed`：先检查 USB 是否识别调试器

2026-10-10 执行 `make flash`，固件构建和 BIN 转换成功，但 OpenOCD 在初始化
ST-Link 时返回 `Error: open failed`、`OpenOCD init failed`，未执行写入和校验。
随后检查 macOS 的 USB 设备列表，没有发现 ST-Link，也没有其他调试程序占用它。

这种情况发生在访问目标 MCU 之前，不应先归因于固件、Flash 布局或 SWD 时钟。
先确认 ST-Link 通过数据线连接电脑且被 USB 识别，再检查板卡供电、共地和 SWD 接线：

- ST-Link SWDIO → MCU PA13。
- ST-Link SWCLK → MCU PA14。
- ST-Link GND → 板卡 GND。
- 按实际探针的供电/参考电压要求连接，勿把 5V 接到 MCU 的 3.3V 电源轨。

macOS 可使用 `ioreg -p IOUSB -l -w 0` 检查 USB 枚举。
USB 转串口或其他芯片的内置 JTAG 设备，并不等于当前 Makefile 配置的 ST-Link。
识别到调试器后重新执行 `make flash`；必须看到写入、校验和复位成功，才能报告烧录完成。

## 8. 不应根据配色注释擅自改变现有视觉效果

原配色中传给 `Rgb565::new` 的部分分量超过 RGB565 范围，实际渲染效果与注释颜色不同。
第一次优化按注释转换成 RGB888，改变了用户原有的配色。这不是已获确认的显示需求，
已恢复原主题和底栏的实际颜色值。性能和可靠性优化应保持用户现有视觉效果。

原底栏从 y=210 开始，覆盖到卡片底部；10×20 字体也使三个状态字段互相覆盖。
底栏改为 y=220、高 20，使用 6×10 字体。默认只显示实际采样次数 `Samples`，
不显示未启用的 ESP/上传状态。ESP8266 通信代码保留。

## 9. 2026-10-10 实板验证

连接后 macOS 识别到 ST-Link（VID:PID 0483:3748，V2J18S4），目标电压约 3.30V。
通过 `make flash` 烧录，OpenOCD 确认 `Programming Finished`、`Verified OK`、
`Resetting Target`。最终固件构建前的 17 项主机回归测试、格式检查和 Clippy 均通过。

使用 `make debug` 和 ARM GDB 检查运行状态：

- 连续采集得到约 26°C、67%RH、1009.8hPa，三个对象均为 `Fresh`，成功时间戳持续推进。
- 在 `Screen::draw_sensor_updates` 中所有 `flush_rect` 返回成功后的 `clear_dirty`
  处命中断点，确认实板局部 SPI 刷新成功；SPI2 状态寄存器无错误，CPU CFSR 为零。
- 在一次采集结束后临时清除 I2C1 CR1 的 PE 位，模拟下一次事务无法推进。
  下一周期温湿度变为 `Stale`，气压仍为 `Fresh`；随后温湿度恢复为 `Fresh`，
  I2C1 PE 自动重新启用，CPU CFSR 仍为零。该测试验证控制器超时恢复及独立采集，
  不等同于拔插传感器或外部器件持续拉低 SDA/SCL。
- 从 AXI SRAM 读回 320×240 RGB565 帧缓冲并转换为 PNG，检查卡片文字、数值、
  历史图与底栏布局。帧缓冲检查和 SPI 返回成功不能替代对实物面板颜色、闪烁的目视检查。

以上为第一版验证，未充分确认连续采样周期。用户随后报告更新停滞，见第 10 节修复。
尚未执行长时间跨 TIM2 回绕运行及物理拔插/卡线测试。

## 10. 单次采集和 SPI 返回成功不能证明持续更新

用户反馈底栏长期停在 `Frame: 1`。GDB 实板调用栈显示主循环停在
`Esp8266::initialize → delay_ms(1500) → cortex_m::asm::delay(600000000)`，
CPU CFSR 为零。ESP 初始化和失败重试直接运行在采集循环中，阻塞期间所有显示更新都被推迟。
软件周期延时的实际耗时也不能仅由主频推算，不能将“有硬件期限调度”当作非阻塞保证。

当前任务只处理显示和采集，因此增加 `ESP8266_ENABLED = false`，默认跳过启动连接与
主循环重试，保留通信代码。屏幕启动等待改用 TIM2 延时。底栏 `Samples` 每次实际采样
递增一次，替代原先每次主循环递增、含义不明确的 `Frame`。

实板验证必须观察多个连续周期的采集时间戳、刷新成功和样本计数，不能只验证一次。
本机 ARM GDB 未启用 Python，批量断点验证应使用普通 GDB 命令文件。

修复版通过 `make flash` 重新写入并校验成功，17 项回归测试和 Clippy 通过。
连续命中 13 次局部刷新成功断点，采样计数从 18 增至 30，温湿度/气压均为 `Fresh`。
后 11 个成功时间戳间隔为 4,999,144～5,000,776µs；刚接入调试时的首个间隔
受暂停/恢复影响为 2.36 秒，不用于周期精度判断。SPI2 SR=0x1002，CPU CFSR=0。
随后再次读回画面，底栏已增至 `Samples: 49`，数值与历史图继续变化，原配色恢复。

## 11. 底栏刷新率应统计成功传输，不能统计主循环次数

底栏增加 `Refresh: x.xx Hz`，按最近一个已完成的 10 秒窗口统计卡片更新。
一轮变化卡片全部传输成功记一次，显示故障恢复后整屏传输成功也记一次；
无脏区域、失败的传输和底栏自身刷新均不计入，避免刷新率被状态文字自身抬高。
它表示应用内容的实际更新频率，不表示 LCD 面板内部扫描频率或 SPI 理论吞吐量。

启动后第一个窗口完成前显示 `-- Hz`；正常每 5 秒采样一次约为 `0.20 Hz`。
一个完整窗口没有成功更新则显示 `0.00 Hz`。使用实际经过时间及回绕减法计算，
保留两位小数并四舍五入，避免定时抖动让 0.19999Hz 显示为 0.19Hz。
主机测试覆盖空闲窗口归零、计数器回绕、延迟轮询和舍入。

`make test` 的 19 项测试、`make check` 均通过，`make flash` 写入并校验成功。
实板连续 4 次刷新成功时，计数从 8 增至 11，统计结果均为 20 centihz（0.20Hz），
CPU CFSR 为零。随后读回帧缓冲确认 `Samples: 16` 和 `Refresh: 0.20 Hz` 并列显示，
无文字重叠，原配色保留。
