# Acquisition：完成一轮采集并保存结果

`Acquisition` 拥有 AHT20、BMP280 驱动、各自的初始化状态、三个测量记录和采样计数。
I2C 总线由运行入口持有，在 `sample` 中短期借用，两个器件顺序访问同一总线。

## 接口

- `Acquisition::default()`：创建尚未采样的组件，不访问硬件。
- `sample(bus, delay_ms, now_us)`：执行一轮采样，更新记录与计数，返回本轮器件读取的 `Result`。
- `snapshot()`：返回温度、湿度、气压及采样计数的副本，不读取硬件。

`delay_ms` 执行驱动要求的有界等待；`now_us` 在各器件成功读取后调用，返回可回绕的
微秒计数。温湿度来自同一次读取，共用时间戳；气压单独取时。
总线实现必须给每次事务设期限，才能与驱动的有限轮询一起保证采样等待有上界。

快照中温度单位为 °C、湿度为 %RH、气压为 hPa。每个 `ReadingSnapshot` 可查询
当前/累计最高/累计最低值、最近六次成功值、状态和最后成功时间。首次成功以前无数值，
真实的零值保留为 `Some(0)`；历史滚动不重置累计极值。

## 失败与恢复

| 状态 | 含义 |
|---|---|
| Pending | 尚未执行采样 |
| Fresh | 最近一轮读取成功 |
| Error | 读取失败，且从未保存有效值 |
| Stale | 最近一轮失败，保留上次有效值及其成功时间 |

一个器件失败不会跳过另一个器件；失败器件在下轮重新初始化。
采样次数按调用轮数增长，包含失败轮次，使用 u32 回绕。
NaN 和无穷不会进入记录，按失败处理；失败不追加历史、不改极值或成功时间。
Stale 由失败触发，目前没有按经过时间自动过期的规则。

## 谁能修改记录

[record.rs](record.rs) 是私有实现，`Record` 仅对采集组件可见，未从库导出。
主循环、显示转换和 UI 都无法取得内部记录的可变引用。
`ReadingSnapshot` 的字段私有，只暴露查询；`AcquisitionSnapshot` 是各查询结果的副本。
调用方即使替换副本中的测量量，也不会改变组件内部状态。

控件输入在 UI 定义，转换放在 [presentation.rs](../presentation.rs)。采集组件不依赖 UI。
记录单元测试留在私有模块内部；宿主机回归通过模拟 I2C 验证设备独立失败、恢复、
快照稳定性和历史/时间戳变化不会造成多余显示传输。
